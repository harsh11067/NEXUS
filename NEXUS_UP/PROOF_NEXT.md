Reviewer-first evidence for the next-feature layer (ERC-8004, deterministic replay, agent card/QR, leaderboard, fiat). Same discipline as `PROOFS.md`: every claim maps to an on-chain tx, a stored artifact, or a repeatable command, and hashes are generated by `gather-proofs.ts`, never hand-typed. Mark testnet rows `[T]`, mainnet `[M]`.

> **Trust model additions:** ERC-8004 validation responses posted by NEXUS carry a **0G Sealed Inference TEE attestation** (hardware-proven inference) plus a trace root (anchored, not kernel-proven). Deterministic replay proves **output reproducibility + fresh TEE re-verification**, not byte-identical signatures (TEE nonces differ). The v1 validator signer is trusted → v2 TEE/ZKP oracle (same honest gap as the base).

## Honest gaps (state them)
- ERC-8004 is **Draft**; the Validation Registry interface is under active revision with the TEE community — pin the exact 0G deployment + interface at build time; if it shifts, the adapter is the only thing that changes.
- Deterministic replay depends on deterministic decoding (temp=0, fixed seed) and provider availability; a model deprecation breaks replay of old receipts → record the provider/model version in the trace and degrade gracefully.
- Validator signer is v1-trusted; v2 moves it into a TEE/ZKP oracle.
