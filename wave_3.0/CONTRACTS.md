## 1. Trust model (state it before the specs)

- **Inference:** hardware-proven — 0G Sealed Inference TEE, verified via `broker.inference.processResponse(provider, chatID)`. A run is `verified` only when that returns `true`; otherwise it is anchored as `unverified` (fail closed).
- **Traces / evidence:** application-level, immutably anchored on 0G Storage + Chain — not kernel-proven.
- **Re-encryption transfer:** v1 uses a trusted ECDSA signer recovered on-chain (`ecrecover`). v2 roadmap moves the signer into a TEE/ZKP oracle. This is the one deliberate trust assumption; it is stated, not hidden.
- **Reputation:** proof-only writes — every `updateScore` carries a `receiptHash`; no free-text reviews can move a score.

## 2. NexusAgent.sol — ERC-7857 Agentic ID

`is ERC721, Ownable`. The agent's identity *is* its encrypted intelligence: the token carries an encrypted-persona reference on 0G Storage, ownership transfer **re-encrypts** the brain for the buyer (seller provably loses access), and clones pay a creator royalty. `transferFrom`/`safeTransferFrom` are **disabled** (`TransfersDisabled`) — ownership only moves through the re-encryption flow.

Key functions:
- `mint(address owner, bytes encryptedPersonaCID, bytes ownerPubKey, bytes32 policyHash, ...) → agentId` — mints, records the persona ref + owner pubkey + policy hash. Emits `AgentMinted(agentId, owner, encryptedPersonaCID)`.
- `requestTransfer(uint256 agentId, address buyer, bytes buyerPubKey)` — owner initiates; emits `ReEncryptionRequest(agentId, oldCipherRef, buyerPubKey, nonce)` for the oracle to act on.
- `finalizeTransfer(uint256 agentId, bytes newCipherRef, bytes signature, ...)` — verifies the trusted signer over `transferDigest(...)`, flips ownership, stores `newCipherRef`. Emits `AgentTransferred(agentId, from, to, newCipherRef)`. **This is the money-shot: after this, the old owner's key can't decrypt the new cipherRef.**
- `clone(uint256 agentId, address to, bytes32 sealedKeyHash, uint256 nonce, bytes signature) → newAgentId` — signer-verified clone with flat creator royalty; emits `AgentCloned(parentId, newAgentId, cloner)`; bumps `cloneCountOf`.
- `authorizeUsage(agentId, executor, permissions)` / `revokeUsage(agentId, executor)` — delegate run rights without transferring ownership.
- Views: `getPersonaRef`, `getPolicyHash`, `ownerPubKeyOf`, `creatorOf`, `cloneCountOf`, `transferDigest`, `cloneDigest`.
- Admin: `setSigner`, `setCloneRoyalty`.
- Errors: `TransfersDisabled`, `NotAgentOwner`, `NoPendingTransfer`, `BadSignature`, `NonexistentAgent`, `RoyaltyTooLow`.

## 3. ProofMeshReceipts.sol — verifiable task sessions

Opens a session bound to an agent + policy hash + task hash, then closes it anchoring the trace CID and the TEE signature. This is the proof spine.

- `openSession(uint256 agentId, bytes32 policyHash, bytes32 taskHash) → sessionId` — requires the caller to own/authorize the agent and the policy hash to match the agent's locked policy (`PolicyMismatch`). Emits `SessionOpened(sessionId, agentId, policyHash)`.
- `closeSession(bytes32 sessionId, bytes traceCID, bytes teeSignature)` — anchors the 0G Storage trace + the enclave signature. Emits `SessionClosed(sessionId, agentId, traceCID, teeSignature)`.
- `flagViolation(sessionId, violationType, evidence)` — records a policy violation.
- Views: `verifySession(sessionId) → (bool valid, bytes32 traceCIDHash)`, `agentOf`, `openerOf`, `getTraceCID`, `getTeeSignature`.
- Errors: `NotAgentOwner`, `PolicyMismatch`, `SessionNotOpen`, `NotOpener`, `UnknownSession`.

## 4. NexusEscrow.sol — policy-bound spending

Native-0G escrow that enforces the agent's spend policy on-chain: max-per-tx, daily budget, allowed merchant. lock → fulfill → settle, with TTL refund and a dispute path.

- `bindPolicy(bytes32 sessionId, uint256 agentId, uint256 maxPerTx, uint256 dailyBudget, address[] allowedMerchants, ...)` — locks the policy for a session. Emits `PolicyBound`. Reverts `PolicyExists` if already bound.
- `lockFunds(uint256 agentId, bytes32 sessionId, address merchant, uint256 amount) payable → paymentId` — enforces `MerchantNotAllowed` / `OverPerTx` / `OverBudget`; locks native 0G. Emits `FundsLocked`.
- `submitFulfillment(bytes32 paymentId, bytes evidenceCID)` — merchant uploads evidence to 0G Storage (structural check: `evidenceHash != 0`). Emits `FulfillmentSubmitted`.
- `settlePayment(bytes32 paymentId)` — releases escrow to merchant after fulfillment; callable by payer or owner. Emits `PaymentSettled(paymentId, agentId, receiptCID)`.
- `refund(bytes32 paymentId)` — TTL-elapsed refund path (`TtlNotElapsed` before). Emits `PaymentRefunded`.
- `openDispute` / `resolveDispute(paymentId, refundBuyer, arbitrationProof)` — arbiter (owner) resolves either way. Emits `DisputeOpened` / `DisputeResolved`.
- Errors include `NoPolicy`, `NotOpener`, `MerchantNotAllowed`, `OverPerTx`, `OverBudget`, `NotMerchant`, `WrongStatus`, `NotFulfilled`, `NotAgentOwner`.

## 5. ReputationRegistry.sol — proof-derived scores

Only whitelisted writers (the receipt minter / proof contracts) can move a score, and every move carries a `receiptHash`. Tiers derived from score.

- `setWriter(address writer, bool allowed)` — owner grants proof-emitting contracts write access. Emits `WriterSet`.
- `updateScore(uint256 agentId, int256 delta, bytes32 receiptHash)` — `onlyWriter`; every change is receipt-anchored. Emits `ScoreUpdated(agentId, newScore, receiptHash)`.
- `flagAgent` / `unflagAgent` — writer flags, owner clears.
- Views: `getScore(agentId)`, `getRep(agentId)`, internal `_tier(...)`.
- Error: `NotWriter`.

## 6. CompositeReceiptMinter.sol — one receipt per verifiable task

Ties a valid session (+ optional settled payment) into a single composite receipt and bumps reputation; the anchor for 0G DA.

- `mint(bytes32 sessionId, bytes32 paymentId?, ...) → receiptId` — requires the session valid (`SessionNotValid`) and, if a payment is referenced, settled (`PaymentNotSettled`); only the session opener or owner may mint (`NotAuthorized`, anti-spam); guards `AlreadyMinted`, `AgentMismatch`. Emits `CompositeReceiptMinted(...)` and writes the reputation delta.
- Views: `getReceipt(receiptId)`, `totalReceipts()`.
- Constructor wires `proofMesh`, `escrow`, `reputation`.

## 7. Contract interaction flow (one verifiable task)

```
mint agent (NexusAgent)  →  openSession (ProofMeshReceipts, policy locked)
  →  run in Sealed Inference (TEE)  →  closeSession (anchor traceCID + teeSignature)
  →  [optional] bindPolicy → lockFunds → submitFulfillment → settlePayment (NexusEscrow)
  →  mint composite receipt (CompositeReceiptMinter)  →  updateScore (ReputationRegistry, receiptHash)
```

## 9. Security properties to preserve on mainnet
- `transferFrom` disabled — ownership only via re-encryption `finalizeTransfer` (prevents "sell the token, keep the brain").
- Signature digests bind agent/nonce; add `address(this)` + `block.chainid` if not already, to prevent cross-deployment replay (verify in `TEST.md` C-tests on mainnet).
- Escrow enforces policy pre-lock; TTL refund guarantees funds can't lock.
- Reputation writes gated to whitelisted proof contracts only.
- Re-encryption oracle is the v1 trust assumption — documented, and the v2 TEE/ZKP path is the roadmap item that removes it.
